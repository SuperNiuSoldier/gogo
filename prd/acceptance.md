## 1. 当前原型差距

最新评审入口为 `design/previews/gogo-next.html`：按 Apple 设计与 prototype 技能重构的影集 / 手账 / 日常三套完整候选，具体方向见[设计候选](prototype-directions.md)，验证见[实施记录](../doc/steps/01-apple-prototype-rebuild.md)。四页五入口、相册、日记、体重、提醒和部分新增 / 编辑 / 撤销操作在内存中实现；照片采用独立双狗生成示例。系统相机、通知、持久化、PDF 文件、数据恢复与异常闭环尚未实施。上轮 `gogo-life` 保留为证据。下表保留重构时对历史 v0.12 的差距分析，不代表新版原型仍使用旧布局。

| 内容 | v0.12 已存在的局部演示 | 新基线还需要什么 |
|---|---|---|
| 导航 | 三入口弹层 | 四个内容页与中央拍照，默认相册 |
| 照片 | 手动轮播和单图日记，两个独立集合 | 统一媒体、自动汇集、散落相册、多图、来源追溯 |
| 日记 | 一张示例卡与简单列表 | 多条真实叠卡、长文、翻阅、全部历史 |
| 体重 | 表单下的小图 | 独立照片成长线与趋势、照片和节点联动 |
| 提醒 | 局部表单和完成逻辑 | 日历、实例、延期 / 跳过、系统通知 |
| 数据 | 当前网页内存 | 本地事务、草稿、重启、迁移、备份恢复 |
| 导出 | 未实现 | 真实 PDF 预览、分页、保存 / 分享 |
| 视觉 | 生成角色封面、纸边修饰 | 内容积累后的四页设计、双主题与真实密度 |

旧浏览器脚本通过仅证明当时的局部交互，不证明 PRD 1.0 已实现，也不替代 Xcode、VoiceOver、Dynamic Type 或真机验证。

## 2. 流程验收矩阵

| 编号 | 场景 | 可判定的预期 |
|---|---|---|
| A01 | 首次无档案 → 建档 | 只必填名字，进入无假内容的相册；可再建第二只 |
| A02 | 五入口与拍照返回 | 四页直接可达；中央拍照不是标签页；取消回来源且浏览位置保留 |
| A03 | 两狗切换与换主题 | 上栏唯一手动切狗，所有页面数据一致；深色可看肉球，浅色可看格林 |
| A04 | 高频五项快记 | 从相册 3 次点击；一天多笔可保存，重复请求只写一次；缺数量不伪造总量 |
| A05 | 日记 0 / 1 / 10 条，纯文 / 9 图 / 长文 | 空状态不造记录；真实叠卡能逐条读；保存后照片自动在相册可见 |
| A06 | 拍照取消、拒绝、失败、重试 | 不生成空记录；保留待存照片；成功只有一个媒体和一个照片日记关联 |
| A07 | 选图与多来源 | 同狗重复导入不重复；称重图不生成第二篇日记；原记录可从图找到 |
| A08 | 移出展示、删记录、删照片、撤销 | 按提示保留或移除正确内容，其他引用不误伤，不留下空日记或断链 |
| A09 | 体重 0 / 1 / 多笔，同时间、无照片 | 空不画趋势；单点不连线；成长线、趋势与明细数值一致；无图不放假照片 |
| A10 | 修正 / 删除早期测量 | 节点、差值、趋势、脚印和新导出同步，另一只狗不受影响 |
| A11 | 提醒周 / 月，逾期和空日 | 今天可定位，实例状态清楚；通知不等于已完成 |
| A12 | 健康完成取消、关联记录、跳过、延期 | 不重复或虚构照护事实；延期不移动整个系列；跳过保留历史 |
| A13 | 周期编辑、撤销、通知权限与调度失败 | 原记录不被旧撤销覆盖；无权限仍能看日历；失败明确，不冒充已通知 |
| A14 | 草稿离开、重启、异步回调到达 | 输入和附件可恢复，不发布到相册；旧结果不能归属新狗 |
| A15 | 保存中断 / 空间不足 / 重试 | 无假成功、无双份、无错误引用；旧数据可读，失败可继续 |
| A16 | 日期、补记、午夜、时区 / 夏令时 | 按规定日历分组；原时间保留；不把过去漏记补成真实完成 |
| A17 | PDF 所选范围、长文、多图、缺文件 | 真文件可打开，数量和数值与快照一致；完整分页，缺失事先列出 |
| A18 | 备份 → 替换测试库 → 恢复 | 狗 / 记录 / 媒体 / 关联一致；损坏或中断时原库可回滚；通知不重复 |
| A19 | 删除档案、最后一份档案 | 明确影响与确认；取消相关通知；共享媒体规则正确；无档案回建档 |
| A20 | 离线、1,000 张图与 10,000 条记录 | 不全量解码原图；列表可浏览、详情可开、导出有进度和取消；耗时与内存用实机报告 |

## 3. 视觉验收

使用同一组有授权的测试照片和合成记录，分别制作奶白 / 黑棕版本。至少覆盖两只狗、未知生日、12 篇日记、不同长宽比照片、6 笔称重、无照片测量、完成 / 逾期 / 周期待办。不得拿参考图中的数据充作用户真实记录。

| 页面 | 与参考对照的重点 | 退回重做的情形 |
|---|---|---|
| 日记 | 焦点卡完整，前后真实记录有层次，照片与正文平衡 | 只有一张示例卡；大面积空白；装饰盖字 |
| 相册 | 多张照片自然形成主画面，主体易辨认，位置可预期 | 固定插画占满首页；功能卡多于照片；随机漂移难点中 |
| 体重 | 照片成长线与趋势两种完整回看 | 只有输入框和缩小折线；用同一头像代替不同时间照片 |
| 提醒 | 日期、事项、完成关系可扫读，新建简短 | 首屏是分类九宫格或多级工具目录 |
| 全局 | 顶部切狗、底部五入口统一，黑白都清晰，中文柔和 | 重复宠物选择器、深色丢失、图标无标签或拍照出现多次主按钮 |
| 文案与功能层级 | 短标签、用户内容、按需出现的反馈；扩展动作在详情或菜单 | 功能说明平铺、重复标题、每个按钮配说明、用口号补空白；删标签后只剩难懂图标 |

对已有内容的四个页面检查：不出现常驻功能介绍段落；空状态引导在有内容后消失；保存反馈不变成永久说明卡。删除影响、权限用途、恢复覆盖和错误恢复仍在对应操作出现，用户日记正文不按产品说明删减。新版已按此规则制作，用户视觉评审与完整产品场景仍待验证。

320 / 375 / 390pt、横屏和最大可用字号检查遮挡、截断、键盘与安全区；必要时叠卡退列表，不丢信息。检查 44pt 点击区、文字对比度、辅助阅读顺序和减少动态效果。对比截图与人工评审均需要，不能只跑 DOM 或数颜色。

## 4. 实施门槛

1. **设计阶段**：本 PRD 与四页、多状态设计一起评审；照片來源不足要明确标注，不用占位演示冒充定稿。
2. **工程基础**：确定部署环境、系统照片能力、持久化和通知方案；先证明记录与照片重启后可恢复，再连接完整页面。
3. **核心闭环**：完成建档、拍照 / 日记 / 快记、共享相册、编辑删除和失败恢复；在相同数据上验证联动。
4. **体重提醒**：实现两种体重回看、日历与通知实例，覆盖异常与时区。
5. **数据交付**：真实 PDF 和整库备份恢复通过，再评估首版完整性。原生阶段未通过不可称“产品完成”。

## 5. 待工程验证或后续决定

| 事项 | 当前可继续的基线 | 在哪个阶段解决 |

| 最低 iOS / Xcode / 设备 | 维持 SwiftUI 方向，不承诺系统 API 可用性 | 工程基础 |
| HEIC / 动态照片 / 批量导入预算 | 按相册需求给明确结果和降级，不继承浏览器限制 | 工程基础原型与真机 |
| 主体抠图质量 | 首版普通照片散落布局可完成；抠图为可选增强 | 视觉验证与后续增强 |
| 用户原始狗照片 | 先明确示例素材来源，不把角色插画当原照 | 四页视觉评审前 |
| 多宠规模和长数据性能 | 至少两宠；A20 的数据量作为验证门槛 | 核心 / 发布验证 |
| 角色陪玩、自动月度故事 | 需求保留在增强范围，不作为已实现 | 独立产品与视觉评审 |

这些未决项不阻塞本轮 PRD 完成；也不应提前标记为已验证。
