更新：2026-10-12。提醒是底栏直接访问的内容页。参考周历、事项清单和短新建面板；完成规则由本项目定义，不能从静态图推断。

## 1. 当天安排

上方为年月、前后周、回到今天与一周日期，选中日有形状和文字状态；有事项的日期加小点，不仅靠颜色。可展开月历，选日后回到当日列表。默认今天、周模式，各狗分别保持当前日期。

下方按未完成、已完成 / 已跳过组织所选日实例；今天额外显示过去未处理的「逾期」条目，数量多可展开，不能把全部历史混进当天列表。已完成项保留完成时间和轻量标记，不直接从视野消失。无事项显示简短空状态与「新提醒」。

事项行主要包含标题、到期时间、状态、完成按钮。点行看详情，低频菜单提供编辑、延期、跳过、删除；不在每行铺四个等权按钮。

## 2. 新建与编辑

只显示事项和日期时间两个必填项，默认当前狗（只读）、类型其他、仅一次；重复与分类按需展开。日期时间无隐含健康推荐，必须由用户选择或确认。一次提醒在创建时要求未来时间，编辑历史完成实例不改写发生事实。

首版类型覆盖喂食、喝水、遛狗、疫苗、驱虫、用药、就诊、洗护、生日、到家纪念和其他。首版重复为一次、每天、每周指定星期；年度重复为后续增强，生日 / 纪念日可先创建某一次，不承诺自动年历。

编辑周期提醒时明确“仅这一次 / 这次及以后”，已完成历史不回写。删除提供“这一次 / 未完成的后续”，默认不删除此前生成的真实记录。保存失败保留设置。

## 3. 提醒实例和完成

每一次到期都有独立实例 ID 和状态：待办 → 已完成 / 已跳过；延期仍是同一待办，保留原计划时间和新到期时间。通知发出或点击通知不算完成。

| 动作 | 提醒变化 | 实际记录 |
|---|---|---|
| 完成普通事项 | 本实例完成，显示真实完成时间 | 创建对应照护记录或其他事件，详情可查看 |
| 完成健康事项 | 先填必要药品 / 项目 / 用量 | 保存成功才完成；取消仍待办 |
| 关联已记的一笔 | 本实例完成 | 用户明确选择同狗兼容类型记录，不重复创建 |
| 跳过 | 本实例已跳过，保留历史 | 不生成照护记录 |
| 延期 | 只修改本次到期时间 | 不生成记录，不移动整个系列 |
| 撤销本次完成 | 恢复原实例状态 | 本次新建记录一并撤销；若关联原有记录，仅解除关联 |

完成与写入为一个事务，用实例 ID 防重复。刚完成可撤销；关联记录或实例后来被修改时，旧撤销不能覆盖新版本，应引导到详情。删除已完成记录不自动重开提醒；删除提醒系列不删除照护事实。

周期按主人设定的本地日历规则生成，基于原定日期而非实际完成时间，避免每天推迟。逾期不能自动当成已完成；多次逾期可合并呈现为数量，但每个实例仍待处理，可逐项或明确批量跳过。不因完成今天一项而凭空补记过去。

## 4. 通知和离线

首次选择启用通知时请求权限；拒绝后提醒仍可保存在 App 日历，清楚显示「未开启系统通知」及设置入口。系统是否送达不能由 App 保存成功推断。通知跳转到对应狗和实例，切换前处理未保存草稿；允许程序定位所属狗，不新增页内选择器。

修改、延期、跳过、完成或删除时同步取消旧通知并重排。调度失败保留待办，显示需重试的状态；系统容量限制通过分批安排和回前台校准处理，技术边界需真机验证，不承诺无限后台通知。

每天 / 每周按设备当前本地时分运行，切时区重新计算未触发实例；旧完成时间保留原时区。夏令时不存在的时刻顺延到当天下一有效时刻，重复时刻只安排第一次。该规则须在原生阶段测试，未通过前不标为支持。

## 5. 验收重点

周月切换、今日定位、无事项、多日逾期、普通完成、健康取消、关联已有记录、跳过、延期、撤销、编辑系列、拒绝权限与通知重排。双狗不得混列；重启后实例及关联保留。完整矩阵见[验收](acceptance.md)。
