# Go狗产品主文档

更新：2026-10-13。原型已获用户确认，首发平台转微信小程序。当前平台约束与工程边界见[小程序首发基线](wechat-release.md)。旧 iOS / 五入口规划已移至[历史归档](../doc/archive/prd-ios-20261013/product-scope.md)。

## 产品定位

Go狗是随手记录宠物生活的小相册。照片、视频和小事是内容主体，常用动作简短，功能填写收进短面板；支持多只宠物，每天多次记录，随时回看。

## 已确认设计

| 约定 | 当前方案 |
|---|---|
| 三个入口 | 相册 / 脚印 / 提醒，默认相册；没有底栏拍照或独立体重页 |
| 相册 | 日记卡片上下滑动，离开阅读位置后模糊；支持照片与视频，视频手动播放 |
| 拍照 | 相册「记一笔」直接拍照，确认后保存，不要求标题或正文；另有媒体导入 |
| 脚印 | 各类小事共用成长串线；喂食、喝水、尿尿、便便、遛狗快记，日记、体重与自写小事短表单 |
| 提醒 | 日历和待办；小程序外通知须按微信订阅授权与模板能力实现 |
| 宠物管理 | 顶部唯一切换；固定＋新增，页头更多编辑当前档案；删除须确认关联内容 |
| 视觉 | 随手写字体、手绘图标、紧凑可读、照片主导；奶白 / 黑棕主题独立于宠物归属，肉球 / 格林形象不融合 |
| 文案 | 不平铺功能介绍；必要操作标签、错误恢复与影响用户决定的存储 / 通知状态保留 |

## 实施与首发目标

1. 本地工程阶段：完成首次建档、照片 / 视频导入、快记、日历待办、编辑删除、草稿、失败处理与重开读取。当前源码实现属于这一阶段，微信真机未验收。
2. 云端与账号阶段：真实 AppID、用户身份隔离、可靠媒体与记录上传、本地缓存 / 离线队列、重试、跨设备恢复、数据删除、可用订阅消息。
3. 发布质量阶段：真机表现、媒体格式、低存储、授权拒绝、无障碍与动效；导出、备份 / 恢复需明确首发验收边界并实际验证，不能用预览页面替代。

扩展照护 / 健康字段、复杂重复提醒、自动故事等仍是待细化规划，不因平台变更伪称已实现。家庭共记、GPS、社区、独立 Android / iOS App 不作为本轮小程序基础工程前置条件。

## 验收原则

- 新用户没有虚构宠物或记录。每条记录及草稿有稳定 ID 和明确宠物归属。
- 常规照护点击类型即可保存；拍照确认后产生关联记录，不重复上传或另建一套图库。
- 相册和脚印读取同一份记录；编辑、删除、换宠后结果一致。
- 保存成功须有持久化结果；失败保留输入和旧数据，清理未完成媒体。删除只清理无引用的自有文件。
- 明确本地已保存、云端已保存和外部已通知的区别。当前本地待办不得显示已发送微信通知。
- 本地开发版不承诺清除微信数据或换机后的恢复，正式云端和导出恢复须有真实验证证据。
- 视觉、动作和数据完整性均以对应运行环境的实测为准；浏览器替身不代替微信开发者工具或真机。
