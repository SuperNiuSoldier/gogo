# 全局宠物、档案与草稿 · PRD 1.0

更新：2026-10-12。顶部头像栏是唯一手动宠物切换入口。肉球和格林的实际档案与奶白 / 黑棕主题分别维护。

2026-10-13 原型补齐：顶部头像栏右侧固定「＋」新增宠物，头像列表可横向浏览；相册 / 脚印 / 提醒页头「…」→「当前狗档案」编辑，档案底部删除。以下正式产品要求仍包含未实现的持久化、备份和通知能力，不能与本次内存原型混同。

## 当前可操作流程

- 新增仅必填名字，头像可选；生日、到家日和小特点放在「更多资料 · 选填」。无头像显示名字首字，不套用肉球或格林照片。
- 保存后切到新宠物的空相册，不生成示例照片、记录、体重或提醒；「记一笔」拍照和照片 / 视频导入可直接使用。
- 改名、更换 / 移除头像、补充资料保留稳定宠物 ID，原记录仍归属它。头像单独保存，不形成相册日记。
- 删除前显示宠物名字、头像、照片 / 视频、记录（含称重）、提醒数量；「保留宠物」、关闭或返回键都不删除。仅「确认删除」执行。
- 删除后转到剩余宠物；没有宠物时显示建档入口并隐藏内容底栏。切换主题和设计方案不会恢复已删除档案。
- 删除时已发起但尚未完成的媒体导入失效，回调不能重新创建该宠物的数据；其他宠物的数据和仍被引用的附件保留。
- 档案未保存时离开可继续编辑或放弃修改；预览内切换设计方案保留输入。尚未接入持久草稿或备份恢复，刷新后本轮更改丢失。

实施与验证见[宠物管理记录](../doc/steps/01-pet-profiles.md)。

## 1. 首次使用与档案

无档案时，显示创建一只狗的简短流程：名字必填，照片、生日、到家日期可跳过；成功后进入相册空状态。不会预置用户不拥有的狗或演示日记。顶部头像栏的添加入口创建下一份档案，至少支持两份；更多档案横向浏览，不在页面内增加第二个下拉框。

名字 1–16 个用户可见字符；未知生日不生成年龄，到家日未知不显示陪伴天数。生日和到家日不晚于今天，到家日已知且生日已知时不得早于生日。估计年龄可作为备注，不冒充精确日期。到家当天第 1 天，按本地日历日计算。

页头菜单「当前狗档案」直接编辑，头像、名字在上，生日 / 到家日 / 小特点按需展开。改名保留稳定 ID，原记录和提醒不换归属。删除档案位于危险操作区，明确照片、记录、提醒数量，提供先备份；确认后取消相关通知并移除数据。共享照片仅在无其他引用时删除；最后一份档案删除后回建档页。

## 2. 一次切换，全局跟随

- 普通内容页一键点顶部头像，当前页面仍保持同一功能，加载该狗的照片、日记、体重、提醒及视图位置；不弹无意义确认。
- 所有页面和编辑器仅显示只读所属名字，不提供全部宠物或第二个选择器。点当前头像无副作用。
- 单条记录详情换狗时回对应内容列表，不能把旧记录的编辑内容换绑到新宠物。
- 主题只控制颜色与视觉语言，不切狗、不改照片和草稿。新用户默认奶白；提供奶白、黑棕和跟随系统，用户选择持久保存。两只主题角色不能变形成一只混色狗。
- 系统通知和导出预览按明确宠物 ID 定位；恢复设置只改变对应偏好，不覆盖其他未涉及状态。

## 3. 草稿与返回

所有新建任务在打开时绑定宠物 ID 和操作 ID。更换主题、异步图片到达或宿主状态变化都不修改归属。

正式版采用持久草稿：未保存正文、照片选择、档案和提醒修改离开时提供「保存草稿并离开 / 放弃 / 继续编辑」。每狗每类编辑器最多一份活跃草稿；已有草稿时先恢复或明确放弃，再开新草稿，不能静默覆盖。草稿不进入历史、计数、相册、PDF或通知。

小表单以模态面板展示时背景头像不可点，用户先保存或退出再在原顶部切狗；完整编辑页若允许顶部操作，也必须先处理草稿。这是原生界面设计规则，取代旧 HTML 非模态弹层的焦点实现。键盘、系统照片选择器和相机都有清晰返回路径。

## 4. 异步与恢复

照片读取、拍照结果、写入重试均绑定发起狗和操作 ID。取消则使该次回调失效；读取完成不等于保存成功。进入后台保留可恢复任务信息；重启恢复草稿需用户继续确认，不悄悄发布。

保存结果过晚到达时只更新原狗数据；当前已看另一只狗，不弹该狗的虚假成功。撤销以具体记录与版本为目标，反馈清楚显示所属狗，不能依赖当前选择决定撤销谁。

头像失败用名字首字或普通占位，不偷换另一只狗的照片；系统图标不冒充真实照片。原生无障碍读取狗名、选中态和切换结果，减少动态效果时直接换内容。
