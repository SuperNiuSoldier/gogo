## 1. 应用骨架

```text
首次使用 → 创建第一只狗 → 相册（默认页）
                       ┌ 全局头像栏：切狗 / 添加狗
                       ├ 脚印：日记叠卡 / 全部记录 → 记一笔
                       ├ 相册：照片散落 / 单张浏览 → 从相册添加
底部固定五入口 ────────┼ 拍照：直接拍摄动作，关闭回到原页
                       ├ 体重：成长线 / 趋势 → 记体重
                       └ 提醒：周历 / 月历 + 待办 → 新提醒
页头菜单 → 当前狗档案 / 外观 / 导出 PDF / 设置
设置 → 数据备份与恢复；后续增强入口见功能清单
```

- 四个内容页共享顶部头像栏，页面标题直接使用「脚印、相册、体重、提醒」，右上菜单提供低频管理。品牌名不压过内容标题。
- 底部中央「拍照」为动作按钮，不是空白标签页。拍照期间保留来源页状态；取消或完成均返回来源页。保存后提供「查看照片」和「补充」，不强迫跳页。
- 首次进入和冷启动默认相册；当前进程从后台返回保持原页。页面来回切换保留滚动位置、当前查看月份及视图选择，各宠物分别保存。
- 页头菜单仅有当前狗档案、外观、导出 PDF、设置，不再次提供宠物选择。选中当前头像不刷新或清空页面。

## 2. 各页第一屏

| 页面 | 主要可见内容 | 唯一主要动作 | 次级操作 |
|---|---|---|---|
| 脚印 | 日记 / 全部视图切换，默认日记叠卡；无日记时有直接写入口 | 记一笔 → 六项快记 | 全部历史的日期 / 类型筛选；记录详情 |
| 相册 | 当前狗的照片墙，照片占顶部与底栏之间主要空间 | 中央底栏拍照 | 添加照片、点照片看大图、按月定位 |
| 体重 | 照片成长线，页头可切趋势 | 记体重 | 点节点看详情、日期范围 |
| 提醒 | 紧凑周历与当天待办；当天可见逾期摘要 | 新提醒 | 月历、完成、延期、跳过 |

相册不会常驻快记六宫格、健康统计或提醒卡。脚印中的「全部」仅一层切换，不再经过“小脚印 → 历史”的嵌套。低频健康记录放在快记面板的「其他记录」，体重和提醒仍由底栏直达，避免重复功能目录。

上表是设计者的页面职责说明，不转写为页面副标题或功能介绍。正常页只显示用户内容、简短标签与当前操作；文案规则见[视觉规范](two-dog-visual-system.md)。

## 3. 动作层级与手势

- 四个内容页在主界面切换。小表单用一个面板；日记长文、记录详情、照片放大使用完整内容页，保留公共头像栏，系统相机 / 照片选择器除外。
- 面板只承载一次新建或编辑，不在其上叠另一张面板。选择其他记录时替换面板内容，并提供返回快记。
- 普通页和浏览详情可直接顶部换狗，详情回到对应列表；新增 / 编辑时按[草稿规则](global-pet-context.md)处理。
- 表单面板遮挡背景导航。需换狗时先保存 / 取消回到顶部头像，不在系统模态表单里再造宠物切换。与旧 Web 非模态实现的区别在实施记录中说明。
- 拖动、滑动都有可见操作替代；删除从详情或菜单触发，不依赖隐蔽手势。返回回来源，切标签不丢未处理草稿，键盘不挡保存。

## 4. 主要任务与点击预算

以下不含 App 启动、输入字符、首次权限或系统相机内部步骤。用于验收日常路径，不以数字宣称尚未完成的性能。

| 任务 | 路径 | 应用内点击预算 |
|---|---|---|
| 从相册记一次喂食 | 脚印 → 记一笔 → 喂食 | 3，成功后停留快记面板，可继续记别项 |
| 在脚印记一次喝水 | 记一笔 → 喝水 | 2，不填数量也能保存 |
| 拍下瞬间 | 中央拍照 → 系统拍摄与确认 → 自动本地保存 | 1 次进入，无额外表单确认 |
| 写日记 | 脚印 → 记一笔 → 日记 → 输入 / 选图 → 保存 | 从相册 4 次，加选图操作 |
| 称重 | 体重 → 记体重 → 输入 → 保存 | 从相册 3 次，照片选填 |
| 设提醒 | 提醒 → 新提醒 → 填事项与时间 → 保存 | 从相册 3 次，加日期选择 |
| 修改过去记录 | 脚印全部 → 点记录 → 编辑 → 保存 | 不经过重新选狗或选类型 |
| 导出当前狗 | 页头菜单 → 导出 PDF → 选范围 → 预览 → 保存 / 分享 | 低频，不追求一键跳过预览 |

## 5. 页面之间共享什么

照片记录、日记、称重都由一个稳定记录 ID 串联；相册从可展示的媒体建立视图，体重从称重记录建立视图，提醒完成关联实际记录。编辑一笔后所有视图同步，返回相册仍能找到同一张图。

当前宠物 ID、主题、日期筛选和草稿是不同状态。主题变更不切狗；页面筛选不修改数据；照片异步处理保留发起时的宠物 ID。完整关系见[数据](data-and-export.md)。

## 6. 状态要求

每页设计加载、空白、部分内容失效、失败可重试、成功状态。无数据时显示一个直接行动入口，不补造示例；加载失败不用“0 条”掩盖。照片处理中只为受影响项显示进度，不遮住可用历史。系统拒绝权限后有解释和替代路径，保存失败保留输入。

本轮未改动旧 HTML；该原型不满足上述导航，后续按[验收](acceptance.md)重建。
