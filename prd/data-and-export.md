# 数据、导出与恢复 · PRD 1.0

平台更新：2026-10-13 首发转微信小程序。当前工程先实现本地持久化，正式版拟采用云端保存＋本地缓存，详见[小程序首发基线](wechat-release.md)。下文的数据关系与恢复质量要求保留；原“首版本地优先、无需注册”不再代表正式云端架构。不上传用户照片或记录做设计素材。

## 1. 一个事实，多处查看

| 对象 | 最小信息 | 使用关系 |
|---|---|---|
| Pet | 稳定 ID、名字、可选头像 / 生日 / 到家日 | 所有记录、草稿、提醒明确绑定 |
| Record | ID、宠物 ID、类型、发生时间及时区、创建 / 修改时间、版本、正文 / 类型字段 | 脚印、日记、体重和导出读取同一笔 |
| Media | ID、照片 / 视频类型、原文件引用、内容校验、格式、时间、尺寸、封面引用、视频时长 | 相册和附件共享文件；衍生图可重建 |
| PetMedia / RecordMedia | 宠物、媒体、来源记录、附件顺序、相册可见性 | 同一媒体可有多来源，相册按当前狗去重 |
| Reminder / Occurrence | 周期定义、宠物、实例 ID、计划 / 到期 / 完成时间、状态、关联记录 | 一次完成不能生成两次照护 |
| Draft / PendingOperation | 归属、编辑类型、输入、临时附件、操作 ID | 失败或重启恢复，不进入正式历史 |
| Preference | 主题、当前狗、每狗视图和浏览位置 | 不与记录混写，不改数据归属 |

数据库框架在工程基础阶段选择，以上是行为约束，不强制具体类名。记录时间统一存储可还原的时间戳和原时区；脚印日分组规则见[日常记录](daily-quick-recording.md)，提醒的本地重复规则见[提醒](reminders.md)。

## 2. 保存与媒体生命周期

- 只有数据和必要附件可恢复地写入本地后，才提示保存成功。记录与附件建立关系必须一致；图片导入和记录提交可分步执行，但中断后可回滚或继续，不留断链。
- 离线可以新建、读取、编辑和导出已在本地的数据；尚未从系统照片库取得原件的项目标记待导入，不承诺已保存。
- 失败重试使用原操作 ID，重复点击不能重复记录。版本冲突时保留当前和待提交修改，不能用过期草稿覆盖更新。
- 删除记录默认保留照片和相册可见性；删除媒体前列出受影响来源，必要时一起删除将变空的照片日记。移出展示只改可见性。
- 撤销一次新建恢复该次操作前状态：新建的未共享媒体一并移除，之前已有媒体仅解除本次引用；修改撤销恢复旧版本。正常删除与撤销的区别需在提示中清楚表达。
- 数据库引用与文件定期核对；只清理已确认无引用的临时或衍生文件，不因加载失败就删除原件。空间不足时保留草稿并显示可理解的原因。

## 3. PDF 是一份可读记录

入口：任一内容页的页头菜单 → 导出 PDF。范围默认当前狗、全部时间和内容，用户可选择日期及日记 / 相册 / 体重 / 照护分类；不在导出里重复切狗。日期范围闭区间，沿用脚印当前时区分组，预览明确范围和条目数量。

输出顺序：封面与狗名、日期范围 → 有实际资料的档案 → 日记和照片 → 体重曲线与测量明细 → 照护 / 健康记录。未知生日或到家日省略，空章节省略。独立导入照片可以进入相册章节；日记 / 体重已出现的同一媒体不重复整页铺陈。隐藏相册的健康附件默认不嵌图片，可明确勾选纳入；相关健康文字随所选类别导出。

先生成真实预览，可翻页确认，再调用系统保存 / 分享。PDF 采用适合打印的浅底，不受当前深色主题影响，正文可读且不在分页处裁掉文字和图；长日记续页，图片保持比例，体重单位和日期清楚。文件名含狗名和范围，非法文件名字符做安全替换。

生成时固定一份数据快照，后续编辑不导致前后页内容不一致。大数据提供进度、取消、失败重试。缺文件时列出缺失项并要求选择继续或修复，不能默默输出空白并称全部成功。取消分享只取消输出操作，不删除记录。

PDF 用于阅读和分享，不能导回恢复数据库；界面清楚分开「导出 PDF」和「备份数据」。

视频在 PDF 中呈现封面和时长，PDF 不承载可播放视频；完整原件纳入数据备份。视频导入和播放规则见[视频导入](video-import.md)。

## 4. 可恢复备份

入口：设置 → 数据 → 备份 / 恢复。首版备份整库，包括全部狗、正式记录、媒体原件、关系、提醒与必要设置；不包含通知系统 ID、失败临时文件和未发布草稿。界面明确包含的狗和数量，不把它冒充当前狗导出。

建议格式为带版本的 `.godog` 文件，内部清单、结构化记录、媒体文件与校验信息；这是格式提案，工程阶段确定版本策略。用户手动选择保存位置，不预置云服务。

恢复采用整库替换，不做未定义的自动合并：选文件 → 校验格式、版本、媒体、引用与空间 → 展示将替换的档案和记录数量 → 确认 → 先保留可回滚的当前快照 → 暂存恢复 → 全部成功后切换。遇到损坏、未知较新版本、空间不足或中断，保持原库可用，不半库覆盖。恢复前已有草稿先处理，明确告知备份不含草稿。

恢复完成后重建衍生图，通知按新库重新安排，移除旧库待调度项；无权限时只恢复日历待办，提示通知未启用。不得重复触发过去提醒，也不把恢复当完成。备份的可用性必须用实际导出 → 清空测试库 → 恢复 → 数量和内容比对验证。

## 5. 质量与容量

首版必须验证多宠、千张照片、跨月记录及长文；原图不一次全量解码，列表按需加载和生成缩略图。具体格式上限、存储预算和耗时需记录测试设备，不借用 Web 原型的限制。

版本迁移保留旧库可回滚副本，失败不清空；升级测试包含记录、照片关联、提醒实例和主题。测试资料使用合成数据或获得授权的素材，真实用户资料不进代码仓库。
