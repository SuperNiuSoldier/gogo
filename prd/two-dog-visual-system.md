# 视觉与双狗规范 · PRD 1.0

更新：2026-10-12。当前构图依据用户提供的四张[参考稿](reference-analysis.md)，替代 v0.12 的插画封面和工具弹层。圆润字体、肉球 / 格林分别识别、黑白双主题继续有效。以下为拟定设计尺度，尚未以新原型验收。

## 1. 四页分别长什么样

| 页面 | 主要视觉 | 排版重点 | 不再沿用 |
|---|---|---|---|
| 脚印 · 日记 | 有前后深度的真实日记纸卡 | 日期轻、正文可读、照片靠一侧，当前卡完整 | 单张大卡加假的多层边框充当多条日记 |
| 相册 | 多张照片组成疏密有序的散落画面 | 照片大小变化、位置稳定，主脸清楚；底栏克制 | 大欢迎语、固定角色海报、整块彩色功能卡 |
| 体重 | 细线串起当时照片和体重 | 数字与日期对齐，节点有呼吸，照片承担情感 | 输入框和保存按钮占据首屏主体 |
| 提醒 | 紧凑日历与轻线事项 | 日期和完成状态容易扫读，新增只有一处 | 多层分类目录、独立大色块通知卡 |

内容先形成层次，少量纸边和浅阴影才有意义。不得给每个面板加胶带、涂鸦、同一只狗贴图和说明口号；不把参考图外围宣传标题放进 App。

## 2. 尺度与密度

以 390pt 宽的 iPhone 设计稿作为常规基准，并验证 320 / 375pt 和大字号。系统状态栏与底部安全区使用实际布局，图中不伪造时间或电量。

- 页面左右边距约 18–20pt；相邻组间 16–24pt，正文和操作之间 8–12pt。大字号时自然增长，不强锁屏高。
- 页标题约 22–24pt 常规字重，正文 16–17pt，日期辅助 12–13pt，输入不小于 16pt。柔和圆体用于标题和正文；数字要清晰，不把功能标签做成难读手写字。
- 纸卡圆角约 14–18pt、细浅阴影，主体照片保留完整比例；不是所有条目都做圆角容器。提醒与全部流水主要用留白和细线。
- 底栏五位置均有文字，四个页入口视觉等重，中央拍照圆形稍突出但不占双倍宽度；至少 44pt 有效点击区。相册有足够内容高度，底栏不遮住最后一项。
- 叠卡只遮相邻卡的次要区域；焦点卡的日期、文字和照片完整。散落照片可轻微旋转约 ±4°，文字和点击区稳定，不模糊照片来模拟参考缩略图压缩效果。
- 每页最多一个主要新增动作；中央拍照全局常驻，其他页面的主动作随其任务变化，不重复放第二个拍照大按钮。

参考尺度是设计提案，不是从截图精确量取。视觉评审要同屏比对内容比例、密度、层次和入口，不能仅检查圆角和颜色。

## 3. 两只狗的独立特征

| 维度 | 肉球 | 格林 |
|---|---|---|
| 毛色与轮廓 | 奶白长毛、蓬松颈毛、厚脚掌 | 黑色胸背、棕色前爪与脸颊 |
| 面部与耳朵 | 立三角耳、深圆眼、深色鼻头带少量粉棕 | 宽垂耳、两点棕眉、深眼黑鼻 |
| 辅助颜色来源 | 围巾的低饱和青绿 | 棕眉与前爪的暖棕 |
| 角色处理 | 保留立耳与白色长毛轮廓 | 保留垂耳与棕眉，不增加白色围脖 |

真实照片始终显示所选狗。主题色可以独立选，不因为奶白主题就把格林照片换成肉球。角色动画与照片相册是不同内容；不把一张照片整体晃动称为狗狗动作。

## 4. 双主题语义色

沿用已确认的[颜色源](../design/theme-tokens.json)，以下为基线。新组件上线前重新验证实际背景组合，旧原型对比度报告不是新页面的自动通过证据。

| 用途 | 奶白 | 黑棕 |
|---|---|---|
| 页面 | `#F7F4EE` | `#17191B` |
| 纸卡 / 表面 | `#FFFDFA` | `#24272A` |
| 次级底色 | `#ECE7DE` | `#303337` |
| 正文 | `#282B29` | `#F5EEE3` |
| 次要文字 | `#626760` | `#BDB6AB` |
| 强调 / 选中 | `#3F655B` | `#D5AD78` |
| 主按钮文字 | `#FFFFFF` | `#201B15` |

小面积强调用于当前页、保存和日历选中；照片仍是最大颜色来源。深色纸卡不简单反相照片，不依靠不可见黑影表示层级。图标使用统一的系统图标语言，标签不能只剩图案。

## 5. 动效与可访问性

页面切换、翻卡和放大照片应保留空间连续性，过渡短而清楚，不持续漂浮页面。系统减少动态效果时使用静态切换；照片播放规则见[相册](photo-album.md)。VoiceOver 按日期和记录顺序读取，不按视觉旋转位置乱序。

日记采用正面上下滑动：中间卡保持清晰和原尺寸，滑离阅读位置后逐渐呈现毛玻璃般的模糊，滑入中间时恢复清晰。相邻卡保留纸边与柔和色块，不旋转、不做透视变形；模糊为显示效果，不改变照片原件。停下后对齐当前篇，标题和底部「记一笔」保持清晰稳定。触屏、滚轮和触控板采用相同方向，键盘提供等效定位；减少动态效果时仅显示当前清晰卡，静态切换。当前实现与专项检查见[滑动与毛玻璃留痕](../doc/steps/01-diary-frost-scroll.md)。

正文和辅助文字目标至少 4.5:1，有效点击区至少 44pt；状态同时用文字或形状。Dynamic Type 下叠卡可退为列表、成长线可改同侧，但内容和主要动作不缺失。不得为了维持参考截图构图牺牲输入、键盘避让和可读性。

## 6. 界面文案与功能呈现

2026-10-12 用户补充：界面中过多的功能说明和功能平铺会产生演示感。正式界面通过内容、位置、图标与反馈说明如何使用；设计理由、能力清单和实现边界留在 PRD、过程文档或预览外部。

- 正常浏览页不放功能介绍段落、按钮副说明、重复的小标题或装饰口号。相册以照片、日期为主，体重以测量和变化为主，提醒以事项和时间为主。
- 页面名、导航短标签、必要字段名、单位和状态保留。减少说明不等于把所有按钮改成无字图标；陌生图标仍配短名称，无障碍名称始终完整。
- 主页面只展示当前任务和内容。扩展动作进入详情或菜单，需要输入时才展示相关字段；不把全部能力改成更短的文案继续平铺。
- 已被照片、折线、选中态或按钮名表达的信息不再重复解释。例如「体重」页不另写“在这里查看狗狗的成长变化”。
- 空状态最多一句简短引导加直接操作；已有内容后撤掉引导。成功反馈短暂出现；错误提示在出错位置说明原因和下一步，不常驻铺满风险说明。
- 删除影响、权限用途、恢复将覆盖的数据、保存失败等决定操作后果的信息，必须在对应时机讲清；不为少字而隐去。
- 用户自己的日记、事项、备注属于内容，应完整可读，不受产品说明的精简限制。长文使用摘要和详情，不删改用户原文。

| 场景 | 正常界面保留 | 移除或按需出现 |
|---|---|---|
| 相册 | 照片、页名、短操作标签 | “照片会自动汇集在这里”等机制说明移到帮助 |
| 体重 | 数值、单位、日期、成长线 / 趋势、记体重 | 不加功能介绍；无记录时才提示“记下第一次体重” |
| 提醒 | 事项、到期时间、完成状态、新提醒 | 不常驻“支持疫苗、驱虫、洗澡……”能力清单 |
| 快记 | 喂食 / 喝水等名称、实际次数、操作后反馈 | 不在每个按钮下面解释“点击即可记录一次” |
| 照片封面 | 用户照片及必要日期 | 删除固定的欢迎语、情绪口号和占位说明段落；演示素材来源在预览外说明 |

评审时逐句确认文字属于内容、识别操作或必要反馈。若只是解释“我们做了什么”，移出产品界面；若删去说明后仍找不到操作，应先修正入口与布局。

## 7. 下一轮视觉交付

四个主页面各提供奶白 / 黑棕两版，同时有空数据、少量内容、数月内容与长文状态；还须展示拍照完成、日记编辑、称重、提醒创建、导出预览。采用同一套示例记录检验联动，示例与真实资料分开标注。

参考中的狗和测量不作 Go狗资产。用户原图在服务器未到位时，应明确这一缺口；不能把重复生成插画占位认定为真实相册设计完成。独立陪玩动画留待增强阶段评审，不延用低清角色大幅铺满首页。
