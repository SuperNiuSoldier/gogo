# Go狗 · 微信小程序工程

当前版本：0.1.0 本地开发版。沿用已确认的相册 / 脚印 / 提醒、顶部统一切宠、奶白 / 黑棕与随手写视觉。使用原生 WXML / WXSS / JavaScript，不套网页，也不需要构建第三方 npm 运行依赖。

## 在 Windows 打开

1. 安装[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)，使用自己的微信登录。
2. 选择「导入项目」，目录选本文件所在的 **wechat** 文件夹（包含 `project.config.json`），不要选择上一级 gogo 或内层 miniprogram。
3. 工程已填入用户提供的 AppID：`wxc34d8754afb8569f`。使用管理该小程序或具有其开发者权限的微信登录；导入时确认 AppID 一致。
4. 点击「编译」，成功后点击「预览」，用具有权限的手机微信扫描工具生成的二维码。首次打开点击「添加宠物」；名称必填，头像、生日、到家日可稍后补充。
5. 拍照 / 相册等能力还需按微信后台要求配置隐私保护指引并在手机验证；如编译、权限或预览报错，保留具体错误信息继续排查。AppID 配置完成不代表账号权限、真机预览、云服务或发布已通过，不需要将 AppSecret 写入前端。

本环境没有微信开发者工具。用户已在 Windows 编译后打开页面，先后反馈的 WXML 表达式错误与按钮挤压布局已修复。本地旧版 WCC/WCSC 编译、114 组浏览器布局和 45 组组件样式冲突检查通过；当前修复版在用户开发者工具和手机上的效果仍待确认。Node / 浏览器检查与编译检查分别记录，具体证据见 `../doc/steps/02-wechat-foundation.md`。

已有工程更新到肉球主题时，将 `godog-wechat-rouqiu-theme.zip` 内的 `miniprogram` 文件夹合并覆盖到当前 `wechat` 目录，然后重新编译。不覆盖 `project.private.config.json` 或用户存储。顶部肉球图标打开主题面板，可选肉球 / 原色，并切换奶白 / 黑棕。v2 使用按用户参考图经 imagegen 生成的照片质感角色与固定背景。

## 当前实现

- 宠物：新增、编辑、头像选择 / 移除、可选日期、删除关联内容确认；最后一只删除后回建档。
- 相册：「记一笔」调用相机，仅拍照；另有照片 / 视频混合导入。上下翻卡、离开焦点的卡片模糊、主动播放照片流转；进入视频卡停止流转，视频详情手动播放。
- 脚印：混合成长串线；喂食、喝水、尿尿、便便、遛狗一键记录，日记 / 体重 / 小事打开短表单；支持详情、编辑与删除。
- 提醒：周 / 月日历、日期选择、新增 / 编辑 / 删除、完成 / 恢复；当前只是小程序内待办，未接微信订阅通知。
- 存储：元数据通过一次同步提交持久保存；媒体复制至 `USER_DATA_PATH/godog-media` 后才写记录；失败回滚、重开读取、草稿保存、失去引用的自有文件清理。
- 风格：主题独立于当前宠物；主题和页面偏好保存；字体为项目已有 Xiaolai 许可子集，缺字交给系统字体；手绘图标复用 Doodle MIT 与项目自绘图标。
- 肉球主题：12 枚 imagegen 照片质感萨摩耶动作 / 表情素材和 1 张固定写真背景；奶白 / 黑棕共用自然白毛图，不反色。快捷入口、串线、底栏与空态统一，没有背景选图功能。原线稿已替换，用户相册记录和头像不改变。见 `../prd/rouqiu-theme.md`。

## 当前边界

- 数据只在本机。清除微信 / 小程序数据、换机无法靠本版本恢复；云同步、整库备份、PDF 尚未实现。
- 本地媒体预算 150 MB；单张照片 20 MB、单段视频 60 MB，每次最多选 9 个。超限明确报错，不丢掉旧数据。
- 本地临时选择路径不能当作永久附件。本工程只引用已复制的用户文件，草稿引用也参加清理保护。
- 默认无演示宠物或记录。肉球主题内置生成的角色 / 背景作为界面素材，不计作相册记录；布局检查的虚构记录不进入小程序运行包。
- iOS / Android 微信中的 HEIC、MOV、HEVC、字体 Data URL、滑动模糊、软键盘和隐私授权待真机验证；模拟测试不代表它们已通过。
- `更多 → 本地存储` 可查看媒体占用与上述限制；`更多 → 减少动效` 可关闭照片自动流转及卡片模糊动效。

## 本地验证

有 Node.js 18+ 时在本目录运行：

```sh
npm test
npm run check
```

无需先安装 npm 依赖。项目服务器使用已有工具链中的 Node 执行同样脚本。微信开发者工具中还需实际点击「编译」，完成下面真机验收。

完整仓库另有 `scripts/check_wechat_compiler.py`：在 Linux 下载并校验固定版本的 WCC/WCSC，编译原始 WXML / WXSS，不登录账号、不上传代码。旧版编译器用于提前发现语法错误，不能替代当前微信开发者工具。`npm run check` 也会直接检查原始模板中的全部绑定表达式，避免 HTML 解析器还原实体后掩盖错误。

布局检查先运行 `scripts/check_wechat_layout.py`，再运行 `scripts/check_wechat_control_layout.py`（需要项目的 Playwright 环境）。后者注入原生按钮默认样式 / v2 选择器冲突样本，实际测量标题、宠物栏、按钮与导航的边界；这些是故障模拟样本，不是完整微信 SDK。工程采用自己的按钮视觉规范，`app.json` 不再启用平台 `style: v2`。

## 账号接通后的首轮验收

1. 创建两只宠物；相册、脚印、提醒均跟随顶部切换；主题不改变归属。
2. 真拍一张照片、选择照片与视频，查看 / 播放后关闭小程序，再打开核对内容。
3. 编辑 / 删除记录和档案；取消删除不会变更，其他狗的内容不受影响。
4. 写一半离开，再打开恢复草稿；拒绝权限、取消选图、存储不足时不显示保存成功。
5. 两种主题、放大文字、减少动效、长名字、小屏幕、软键盘、前后台切换和视频格式逐项记录设备结果。

后续云端保存和订阅消息的接入计划见 `../doc/steps/03-wechat-cloud.md`。
