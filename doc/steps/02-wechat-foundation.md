- 新建宠物 → 拍照 / 导入 → 保存 → 重新初始化仓库后内容和媒体引用仍在。

## WXML 编译错误修复

2026-10-13 用户已正确导入 `wechat`，Windows 微信开发者工具 Stable 2.02.2608080 报 `pages/home/index.wxml:56:23: Bad attr wx:if ... unexpected ; at pos36`。

原因：第 56 行的 `&&` / `<` 被写成 `&amp;&amp;` / `&lt;`，第 116 行也有相同的逻辑与转义；WXML 表达式要求直接写运算符。之前的浏览器布局替身通过 HTML 解析器自动解码，掩盖了错误；旧静态检查仅确认存在绑定括号，未编译表达式。

实施：

1. 将上述两处运算符恢复为原始表达式，保留分页与错误提示行为。
2. `wechat/scripts/check.js` 在 HTML 解析前检查全部 249 个原始绑定表达式，保留原文件及行号定位。它仍不宣称能替代完整 WXML 语言编译器。
3. 新增 `scripts/check_wechat_compiler.py`，从 npm 固定下载 `miniprogram-compiler@0.2.3`，校验 SHA-512，只提取 Linux 编译器与许可文件。工具缓存和编译输出均在 `.tools/wechat-compiler`，不进入运行包，不安装运行时依赖，不登录或上传代码。
4. 重新打包完整源码，并提供 `wechat/dist/godog-wechat-preview-fix.zip`，仅覆盖 `miniprogram/pages/home/index.wxml`，不改用户本机配置。

验证：

- 旧源码在 WCC 中复现同一第 56 行报错；只修复第 56 行后，第 116 行也会报错。补充的原始表达式检查对两个错误样本均返回失败，对修复版返回成功；证据为 `design/previews/wechat/template-regression.json`。
- 修复后的整页 WXML 与全部 WXSS 编译成功，退出码均为 0，无编译诊断。版本为 WCC `v0.5vv_20200413_syb_scopedata` / WCSC `v0.4me_20190328_db`，证据为 `design/previews/wechat/compiler-check.json`。
- 工程静态检查通过，249 个绑定表达式均可解析。此次未改变业务 JavaScript 或样式，不重复上一轮 29 项逻辑 / 96 组布局测试；这些仍属于上一轮证据。
- 上述旧版编译器检查不能代表用户当前 Stable 工具版本、模拟器、相机、字体、视频或真机已通过。下一步是用户覆盖修复包后重新编译，页面打开后再点「预览」扫码。

## 原生组件布局修复

2026-10-13 用户已打开相册空状态，截图显示顶部宠物被裁切、「相册」竖排、分段按钮过宽、「记一笔」被挤成圆形。用户截图证明页面可运行，不能把此时的布局视为验收通过。

原因与依据：`app.json` 启用了 `style: v2`；[微信全局配置文档](https://developers.weixin.qq.com/miniprogram/dev/reference/configuration/app.html#style)说明该配置改变包括 button 在内的组件默认样式。原实现的低优先级 `button` 重置和单类尺寸规则不能可靠覆盖平台的属性选择器，宽度、自动外边距和内边距挤占横向空间。旧浏览器检查仅使用 HTML 按钮，遗漏了这层组件规则。补入较高优先级的 184 px 宽度 / 自动外边距 / 内边距冲突样本后，旧源码可复现标题竖排与按钮变形；该样本是针对问题的模拟，不宣称完整复制用户当前微信基础库。

实施流程：

1. 关闭 `style: v2`，继续保留原生按钮行为以及已确认的手绘视觉。
2. 为全部 45 个按钮增加 `gogo-button` 基础类，在 `.app` 下重置宽度、外边距、内边距和边框；按钮变体以同级或更高优先级明确尺寸，保留主按钮 / 禁用状态 / 导航状态。
3. 宠物列表放入独立的内层横排，固定滚动栏高度；顶部图标固定 44 px，标题保持单行，分段按钮固定 54 px，主按钮不被压缩且至少 136 × 48 px。多宠物长名字横向滚动，不挤压添加与主题按钮。
4. 浏览器检查加入组件基线 / v2 冲突样本，修正原生标签选择器到浏览器标签的映射，移除会掩盖输入框 / 日期按钮尺寸问题的额外样式。新增空相册和多宠物长名字场景。
5. 更新完整源码包；`godog-wechat-layout-fix.zip` 提供四个累计修复文件：`miniprogram/app.json`、`app.wxss`、`pages/home/index.wxml`、`index.wxss`。旧 `godog-wechat-preview-fix.zip` 下载地址也更新为这份累计修复，避免覆盖回旧模板。无需清除用户存储或更改本机项目配置。

验证结果：

- 114 组浏览器布局检查通过：320 / 375 / 430 宽度，双主题、三页与表单，新增单宠空相册和八宠长名字，部分 125% 字号；无根容器横向溢出、导航 / 面板越界或图片缺失。
- 45 组控件边界检查通过：五种页面状态 × 三种宽度 × 100% / 125% / 150% 字号；在修复后的页面末尾再注入 v2 冲突规则，仍保持标题单行、宠物栏宽度、44 px 图标按钮、完整主按钮及等宽导航；八宠场景可横向滚动。
