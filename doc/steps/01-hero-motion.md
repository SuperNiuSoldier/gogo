# 首页狗狗动态展示 v0.7

日期：2026-10-10。阶段 01 进行中。

历史方案：用户随后明确否定了整图晃动，本方案由[角色动作帧 v0.8](01-character-animation.md)取代。下列通过结果仅指当时的技术检查，不代表用户接受该效果。

## 输入与实现

用户圈出首页宠物卡片，希望动态展示。使用项目内 UI UX Pro Max 查询 `reduced motion pause animation`，结果对应系统动态偏好、限制单页动画数量和按场景选择时长；采纳单一角色区域动画与可暂停的方案。

1. 留存 v0.6 原型、首页截图及检查记录到 `design/previews/archive/*v06*`。
2. 把原来的展示图片改为可用触控 / 键盘操作的狗狗按钮；保持插画和背景颜色，使用内层变换表现呼吸与间歇晃动，静态容器不移动。
3. 为肉球、格林设置独立节奏和摸头回应；点击不增加照护记录。暂停操作、切换宠物、离页和系统设置变化会清理尚未结束的回应。
4. 添加暂停 / 播放、系统减少动态效果、页面可见性和组件可见性处理。暂停偏好进入宿主私有状态；照片、日记、提醒内容仍不进入宿主状态。
5. 更新圆体子集和当前产品方案。没有生成新角色图片或使用竞品资产。

## 验证

- [动态浏览器检查存档](../../design/previews/archive/motion-browser-checks-v07.json)通过：两只狗使用不同动画、实际变换随时间更新、点击和连续点击、暂停冻结 / 清理回应、静态文字回应、切狗清理、主题与图像独立、点击不增加记录、离页暂停、模拟后台暂停、实时系统动态偏好、键盘操作和暂停偏好恢复。无 JavaScript 运行错误。
- 两套主题在 320、375、390px 和 844×390 横屏共 8 组动态区域布局检查通过，狗狗按钮和暂停按钮均至少 44×44 CSS px，且点击区不重叠。
- [首页回归存档](../../design/previews/archive/browser-checks-v07.json)的 15 组布局及已有快记、撤销、补记、表单、筛选、删除确认通过；未将本次检查等同于完整二级业务重测。
- 检查中修复：从系统减少动态效果恢复时清理上一轮文字回应，避免恢复后短时间内的第一次点击被旧的防重复状态挡住。
- 字体扩展到 457 字符，源字形覆盖及浏览器加载通过；JavaScript 语法、本地 Markdown 链接与片段格式检查通过，当前约 355 KB。
- 两套首页已目视检查。原有回归截图是在减少动态效果模式下生成，用于确认静态退化与布局；运动变化通过浏览器计算样式的时间采样验证。
- 脚本：[check_hero_motion.py](../../scripts/check_hero_motion.py)、[check_companion_preview.py](../../scripts/check_companion_preview.py)。实际视口滚出场景及原生后台行为尚未单独做真机检查。

## 边界

当前是插画变换动效，不是视频、三维模型、独立部位骨骼或逐帧表情。原生 iOS 实现、VoiceOver、系统字号、后台能耗、低电量模式和真机动画流畅度未验证。照片 / 档案 / 提醒等仍为临时内存原型。本轮未提交或推送仓库。
