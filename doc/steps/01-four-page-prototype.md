# 四页交互原型：照片、纸卡与日常回看

日期：2026-10-12。阶段 01 继续进行；本轮制作可评审的视觉与交互原型，未建立 Xcode 工程，未提交或推送 Git。

## 输入与设计依据

用户在了解 Codex 原型设计方式后授权「好的，开始」。沿用已确认的五入口：脚印、相册、拍照、体重、提醒，默认相册；顶部是唯一切狗位置，肉球与格林保持独立身份，主题可单独切换。当前要求集中在贴近用户参考稿、减少说明文字、内容成为主角以及整套页面的完成度。

本轮逐页对照 `design/references/tupina` 中的四张设计图：借鉴日记前后叠放、散落相册、照片体重线和紧凑日历；不复制对方照片、宣传文案或产品标志。没有将旧 v0.12 的三入口工具弹层继续当作新版布局。

## 实现内容

| 部分 | 当前可以操作的内容 |
|---|---|
| 全局 | 四个主页面直接切换，拍照独立动作；顶部切狗、黑白主题互不耦合；模态表单锁定当前宠物 |
| 相册 | 每只狗六张独立示例照片构图，单图查看与前后翻页，按需播放 / 暂停；焦点进入其他照片控件或减少动态效果时停止播放 |
| 脚印 | 基于不同日记数据的纸卡，前后翻阅和全部流水；喂食、喝水、尿尿、便便、遛狗一键保存及撤销，日记短面板与补记 |
| 日记编辑 | 新建、详情、编辑、删除及撤销；长文完整保留在详情；纯照片日记也可保存；关闭未保存表单可继续编辑 |
| 体重 | 真实不同测量对象组成的照片成长线；同一组数据计算趋势和差值；新增、编辑、删除、撤销；没有照片时不放假头像 |
| 提醒 | 周历 / 月历、上一周月、今天定位、日期对应事项；新增、编辑、删除及完成 / 撤销完成 |
| 媒体 | 浏览器文件选择；拍照输入的结果进入相册并产生一篇照片日记；日记 / 体重复用同一照片 ID，切狗后各自独立 |
| 回忆册 | 从相册菜单查看由当前日记和体重组成的排版预览；没有声称已生成 PDF 文件 |
| 评审状态 | 宿主控件切换空 / 一条 / 多条内容及 125% 文字；更换内容状态重置模拟数据，调整文字大小保留当前记录 |

常驻页面删去功能介绍、欢迎语和能力说明，仅保留页面名、短操作、日期与用户内容。输入字段在新建 / 编辑时出现。卡片和照片用轻量边线与层次，提醒采用行和细线；全页没有彩色功能卡目录。

## 检查与修正

检查脚本：[scripts/check_life_preview.py](../../scripts/check_life_preview.py)。浏览器为项目内 Playwright Chromium；环境适配、缓存与包装页面均在 `.tools`。这些结果只验证浏览器原型，不代替原生验收。

本轮在实际运行与截图中修正：

1. 预览宿主标题 / 段落覆盖字体导致缺字，改为产品根下统一继承圆体；所有静态文本字形包含在子集中。
2. 表单原生提交在预览沙箱被限制，保存改为本地显式校验与处理，保留 Enter 提交与错误反馈。
3. 未保存日记恢复时可能丢失输入框的实时值，改从编辑对象重建；新日记保存后定位到相应卡片。
4. 格林日记行数较多导致底部翻页按钮挤进滚动边界，翻页移至固定操作行；前台卡文字和照片继续完整可读。
5. 去掉两处重复选图按钮、照片卡上被相邻卡遮挡的日期；加强输入边界和月历非本月日期的可读性。

最终浏览器 12 组检查通过，见[交互报告](../../design/previews/gogo-life/browser-checks.json)。覆盖五入口与上下文、快记撤销、日记新建 / 编辑 / 草稿、体重数据联动、提醒日历 / 完成、照片浏览 / 播放 / 文件选择、空 / 一条 / 多条、回忆册与长文。无 JavaScript 运行错误。

320 / 375 / 390px 内容宽度及横屏容器、常规 / 125% 文字，共 32 组布局组合通过，见[布局报告](../../design/previews/gogo-life/layout-checks.json)：主页面操作区无外溢，点击区至少 44px。体重趋势下方照片明细为可横向浏览的连续栏，末项详情已实际点击检查，不把滚动轨道外的内容误算为页面溢出。这不是 Dynamic Type、软键盘或系统安全区验证。

正文、次要文字、选中按钮及输入边界共 20 组实际颜色组合通过目标对比度检查，见[颜色报告](../../design/previews/gogo-life/contrast-checks.json)。相关文档本地链接无失效路径，见[文档报告](../../design/previews/gogo-life/document-checks.json)。

## 尚未完成与限制

- 这是内存原型，关闭或重开会丢失临时记录与选入图片。只保存所选页面、宠物及主题偏好到宿主，不保存个人内容。
- 未验证 iOS 真机拍照、相册权限 / 拒绝、HEIC / 动态照片、通知、VoiceOver、Dynamic Type、软键盘与安全区。浏览器文件选择通过不等于相机硬件验证通过。
- 预览不提供完整建档、健康专属字段、提醒周期 / 延期 / 跳过与完成关联照护、原生草稿事务、媒体内容去重、真实 PDF、备份恢复或大数据性能。完整 PRD 的 A01–A20 不标为通过。
- 参考照片目前仍为生成示例，需要用户原照后才能评审真实素材适配。用户选图在详情也暂为方形裁切，原比例与缩放查看留待后续。
- 选图编辑时新导入图片立即进入相册，取消表单不会回滚这张图片；与 PRD 原生事务目标有差距。单次预览读取最多 20 张、每张 20MB，最长边缩至 1600px；不冒充正式媒体存储方案。
- 角色陪玩动作留待增强阶段，没有把相册照片晃动当作狗狗动画。

下一步是对这套四页和简短表单做用户视觉 / 交互评审，确认后进入原生工程基础，首先验证本地保存和系统媒体能力。
