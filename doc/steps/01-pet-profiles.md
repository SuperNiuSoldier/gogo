# 宠物新增、编辑与删除

日期：2026-10-13。阶段 01。

## 本轮输入

用户确认将此前缺失的宠物增删入口加入当前预览。沿用[全局宠物约定](../../prd/global-pet-context.md)，共同更新主原型和字体对照稿，不选择或替换现有视觉候选。

## 实施过程

1. 将固定的肉球 / 格林改为共享宠物字典。初始仍展示两只狗的样例，用户新增的宠物从空记录开始；切换方案保留档案，删除后不会被重新初始化。
2. 顶部头像列表增加横向浏览，右侧固定「＋」；新增表单仅名字必填，头像可选，生日 / 到家日 / 小特点收进选填区域。无头像用名字首字占位，未采用其他狗的照片。
3. 三个页面的「…」菜单统一提供「当前狗档案」，支持改名、更换 / 移除头像和补充资料。名字按用户可见字符校验 1–16 个字，日期检查未来值及到家日早于生日；档案修改保持 ID 与记录归属。
4. 删除放在档案底部，先展示名字、头像、照片 / 视频 / 记录 / 提醒数量，再明确确认。关闭、Escape 和「保留宠物」返回档案。执行后清理该宠物的记录与独占媒体，其他宠物及仍有引用的附件保留。
5. 删除最后一只进入建档空页并隐藏底栏；重新添加后可以正常拍照和导入。媒体导入回调检查目标宠物是否仍存在，避免删除后重建孤立记录；失效临时视频 URL 释放。
6. 头像独立于相册，不自动生成日记；异步读取期间禁用保存，放弃编辑、替换选择或重建方案时不把旧回调写入新档案。表单沿用未保存退出确认，设计方案切换保留文字草稿。
7. 人工检查发现首字占位被通用图片样式覆盖、危险按钮被普通按钮颜色覆盖，已提高对应规则优先级；新增空头像栏去除无内容底色。预览字库仍为固定文案子集，动态姓名使用系统中文字体补全。

源码：`design/prototypes/gogo-next/{app.js,style.css,view.html}`、`design/prototypes/gogo-lettering/style.css`。字库子集、构建报告与两份预览随构建更新。`gogo-lettering/view.html` 为生成模板。

## 验证

专项脚本：[check_pet_profiles.py](../../scripts/check_pet_profiles.py)。记录为[宠物检查](../../design/previews/gogo-lettering/pet-profile-checks.json)，同份结果保存到主原型目录。脚本先使用视频检查生成的合成素材，再验证档案行为；不使用真实用户资料。

已通过 11 组宠物专项检查、12 个布局场景，无 JavaScript 运行错误；以下均为 Chromium 浏览器结果，未标记原生或真机通过。

- 主原型三个方向、字体对照三个方向：必填 / 空白名字校验、新宠物无示例记录、独立主题、快记 / 称重 / 提醒归属、改名保留 ID、删除数量、取消 / Escape / 确认、其他宠物数据保留，以及切换方案不恢复已删除档案。
- 未保存表单的继续 / 放弃、长名字与日期校验；头像上传、移除、跨方案保留，头像不污染相册；含 HTML 符号的名字按文本显示。
- 视频归属宠物删除后释放 Blob URL；删除最后一只、建档空页跨方案保留、重新建档并导入。
- 导入照片 / 视频的批次尚未结束时删除宠物，旧回调不写回，临时视频释放。[补充结果](../../design/previews/gogo-lettering/pet-async-checks.json)也单独保留。
- 多宠、长名字、320 / 375 / 390px、常规 / 125% 字号、明暗主题共 12 个布局场景；横向头像栏、固定新增按钮、档案和删除弹层无横向溢出；减少动态效果时不播放弹层位移动画。
- 最终补查[六个方向的头像栏](../../design/previews/gogo-lettering/pet-header-checks.json)：在 320px、多宠、长名字情况下切换方案，选中宠物保持可见；首字头像居中，危险按钮颜色独立。人工查看最终档案与删除弹层截图。
- 原有[视频导入 13 组检查](../../design/previews/gogo-lettering/video-import-checks.json)通过；[提醒 8 组流程与 18 个布局](../../design/previews/gogo-lettering/browser-checks.json)回归通过，均无 JavaScript 运行错误。

Linux 检查环境没有可用的系统中文字库。宠物专项脚本以项目内已获许可的完整霞鹜 / 小赖字体提供进程级系统后备字体，配置和缓存位于 `.tools`；未修改系统目录，也未将完整字体塞入预览。截图据此检查动态姓名，iPhone / Windows 的实际系统后备字体仍需各自验证。

## 遗留边界

- 仍为内存原型。刷新后档案与导入内容重置；本地数据库、持久草稿、备份恢复、系统通知取消和真机照片权限尚未实现。删除确认中的提醒是预览内记录，不代表已调度系统通知。
- 正式版要求删除前可备份；本轮未提供没有实际备份能力的按钮。原型共享附件防护保留引用，但跨宠物共享附件尚无可操作创建流程。
- 已有样例狗保持原照片和独立黑白主题；新增狗不会自动生成新主题或把两只狗外观混合。自定义输入可能使用系统后备字形，不能把预览子集当作完整生产字库。
- 未提交、推送或写入 Figma。阶段 02 原生工程仍未开始。
