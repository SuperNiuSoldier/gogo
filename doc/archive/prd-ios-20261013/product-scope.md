## 1. 产品要解决什么

Go狗是一册能随手记录的宠物生活相册。打开先看到自己的狗，拍下的瞬间自然汇入相册；照护几下就记好，回看时能看到每天的故事、体重变化和待办安排。适用于每天多次记录、同时照顾多只狗的主人。

高频照护和照片回看同为主线。功能完整依靠明确页面、共享数据与短操作，不依靠首页铺满功能卡片。完成标准是用户连续使用一段时间后，内容仍能找回、修改、导出和恢复。

## 2. 已确认约束

| 编号 | 用户要求 | 当前决定 |
|---|---|---|
| C01 | 尽量贴近提供的设计稿 | 以叠放日记、照片相册、照片体重线、日历提醒作为主要页面骨架 |
| C02 | 五入口导航（本轮确认） | 脚印 / 相册 / 拍照 / 体重 / 提醒；四个页面加一个动作，默认进入相册 |
| C03 | 大面积看狗，功能收起 | 相册承担首页；新增、编辑和低频选择使用短面板；内容回看占完整页面 |
| C04 | 每日高频，交互简单但功能齐全 | 六项快记固定为喂食、喝水、尿尿、便便、遛狗、日记 |
| C05 | 只在上栏切一次宠物 | 全局头像栏唯一切换，所有页面自动跟随，无页内宠物选择 |
| C06 | 肉球、格林各有特点 | 角色独立，保留奶白 / 黑棕主题；换主题不改记录归属 |
| C07 | 字体柔和，避免过量留白 | 圆润中文、紧凑但可读；照片形成疏密变化，不用空区域撑页面 |
| C08 | 拍照只为留个瞬间 | 中央拍照直接进入拍摄，确认照片后保存，文字和时间事后可补 |
| C09 | 动态展示 | 照片可流转；角色动作使用独立形象和真实动作帧，两者分别设计 |
| C10 | 不平铺功能描述，减少界面说明 | 内容和操作本身表达功能；正常页无介绍段落，必要标签与情境提示保留 |

五入口取代旧「脚印 / 回忆 / 更多」三入口。旧版所有功能都套在首页弹层内的布局不再沿用；“功能折叠”保留给填写和选择，不让相册、体重、提醒只能挤在短弹层里。

## 3. 首版完整范围

以下为本轮提出的完整首版目标，分阶段实现但不以演示页面替代。工程尚未开始，细节均需验证。

| 领域 | 必须完成的闭环 |
|---|---|
| 档案与上下文 | 创建多份档案、用户头像、编辑、切换、移除；至少肉球 / 格林两份独立使用验证 |
| 脚印 | 五项一键照护、文字 / 多图日记、全部历史、补记、编辑、删除、撤销 |
| 照护与健康 | 洗澡、美容、训练、自定义、第一次；疫苗、驱虫、用药、就诊及照片附件 |
| 相册与拍照 | 拍照、选择系统照片、自动汇集记录附件、散落相册、单图浏览与流转、移出首页与彻底删除 |
| 体重 | 实际称重、选填照片、照片成长线与趋势切换、修改和删除，回看同一份数据 |
| 提醒 | 周 / 月日历、一次 / 每日 / 每周、完成与关联记录、跳过、延期、系统通知授权和失败处理 |
| 数据 | 离线本地保存、重启恢复、草稿、版本迁移、按当前狗导出 PDF、整库备份和恢复 |
| 表现 | 双主题、清楚的文字标签、减少动态效果、无障碍阅读、真实数据量下可用 |

月度回看由相册按月定位及 PDF 日期范围承接。自动生成月度故事、两张成长照片对比、独立分享海报、快捷项自定义和角色陪玩列为后续增强，保留需求而不伪装首版已完成；角色陪玩需独立质量评审。云同步、家庭共记、GPS、社区、消费统计、徽章、Android 暂不进入首版。

## 4. 成功标准

- 已选宠物时，从默认相册页记一次常规照护不超过 3 次点击；已在脚印页为 2 次，不包含系统启动。计数依据见[流程](../../../prd/mvp-design.md)。
- 拍照不要求先选类别、再填标题；用户在系统拍摄确认后即可留下瞬间。
- 日记中的照片保存一次就能在相册看到；体重的照片与测量关联；从照片能找到原记录。
- 四个内容页在空数据、少量数据、数月数据时都有可用布局。新用户没有虚构日记、体重或提醒。
- 重启后照片、数据与关联不丢；失败不显示成功，重试不重复；PDF 与恢复备份都经过真实文件验收。
- 第一眼能分清脚印、相册、体重、提醒，打开页面不用再找“功能目录”。

这些是验收目标，尚无真实使用指标。质量门槛详见[验收](../../../prd/acceptance.md)。

## 5. 当前状态与工程边界

本轮只重构 PRD 和实施计划。旧原型仅验证了局部交互，内存记录、生成角色、表单下方小图表和单张纸卡不能代表本方案已落地。下一次视觉交付应同时展示四页及关键状态，使用获得授权的多张真实照片或明确标注的示例内容。

技术方向维持 iOS / SwiftUI / 本地优先。最低 iOS、照片衍生图处理能力、存储实现与真机环境在工程基础阶段确定，不在 PRD 中伪称已验证系统能力。共享数据规则见[数据与导出](../../../prd/data-and-export.md)，逐页行为见[信息架构](../../../prd/mvp-design.md)。
