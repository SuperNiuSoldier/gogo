# 回忆、档案与提醒（当前交互 v0.11）

日期：2026-10-10。状态：可操作的浏览器原型，待用户评审；原生 iOS 业务尚未实现。沿用[陪伴首页](companion-home.md)的圆体、紧凑布局和肉球 / 格林独立主题。

这些内容在首页功能栏打开的面板内使用，展示照片与照片日记为独立集合。v0.11 所有页面只跟随顶部当前狗狗，不再在页面内选择宠物；详情见[顶部统一切换](global-pet-context.md)。

## 回忆：以照片和故事为主

- “回忆”只看当前狗狗的照片 / 文字日记与既有里程碑；完整照护流水从“小脚印”进入，两者都没有狗狗 / 类型选择器。
- 只保留「照相 · 留个瞬间」主按钮，照片返回后直接记下一条回忆，可再补文字或撤销。里程碑创建位于「更多 → 第一次」；已有纯文字日记保留。
- 日记至少有一张有效照片或非空文字。当前原型支持一张 JPG、PNG 或 WebP，最大 5 MB；多图、HEIC、系统照片选择器在原生阶段实现。
- 照片读取中显示状态并暂停保存；无法打开、文件过大、换图失败保留其他内容。取消选图不清空文字，移除照片属于未保存修改。快速连续选图时，旧请求不得覆盖新选择。
- 里程碑必须填写“第一次”的内容，照片选填；不能只放一张无说明照片就生成里程碑。
- 新增回忆使用顶部当前狗狗；照片返回前固定该 ID。没有全部狗狗视图，编辑已有记录始终保留原狗狗 ID；切换有未保存内容时先确认放弃。
- 示例回忆中的角色图标注为“示例插画”，不是用户真实照片。

## 档案：直接编辑

从「更多 → 档案」直接编辑顶部当前狗狗；默认显示名字，生日、到家日期和小特点放入「补充信息」；更换档案对象只用顶部头像。名字为 1–16 字，其他内容可空；未知日期不生成年龄或陪伴天数。日期不得晚于今天，到家日期不得早于生日。

正式版如展示陪伴天数，按设备本地日历日差加一计算；当前简化表单保留到家日期，不再额外展示概览。改名只改变显示名，记录和提醒仍绑定稳定的狗狗 ID；肉球 / 格林主题工作名及参考形象保持独立。

有改动时取消需确认，校验失败保留输入并定位错误字段。原型暂不提供新增 / 删除档案和更换档案头像；正式版仍需至少支持两份独立档案及用户自己的照片。

## 提醒：完成后才记一笔

入口位于「更多 → 提醒」。快记弹层只显示当前狗狗最早的一项有效提醒，没有提醒时不占位置。提醒列表明确展示当前狗狗，不混用两只狗的项目。

默认显示事项名称与未来时间；类型与重复规则放入「重复与分类」，默认其他、只这一次；原型支持一次、每天、每周。事项类型包括喂食、喝水、遛狗、用药、疫苗、驱虫、就诊和其他。标题必填，保存时间必须在未来。

1. 保存提醒只创建待办，不增加已发生记录。
2. 点击“完成并记录”：普通照护创建一条当前时间的记录；用药 / 疫苗 / 驱虫 / 就诊必须先填写实际内容；其他事项直接沿用提醒标题，成功保存后才完成提醒。取消或校验失败时提醒仍有效。
3. 一次提醒转为已完成；周期提醒按本地日历推进到下一次未来时间，保留时分。逾期多个周期只记录本次真实完成，不补造之前的记录。提前完成也会推进一个周期。
4. 提醒完成与生成记录是一项可撤销操作：撤销同时删除新记录、恢复原提醒。使用提醒 ID 和本次到期时间校验，另设 650ms 防误触保护，不重复完成下一周期。
5. 编辑 / 删除提醒会结束该提醒先前的“完成”撤销机会，避免旧撤销覆盖新安排。已经生成的记录仍保留，可独立编辑或删除；删除一条记录不自动重开提醒。
6. 删除提醒和放弃未保存修改均需确认。已完成的一次提醒可通过“重新安排”设置未来时间；不能无提示自动重启。

当前提醒是在预览中验证流程，不发送系统通知。通知授权、拒绝后的引导、后台调度、跨时区 / 夏令时、跳过 / 延期、已有记录关联等仍待原生阶段设计与验证；不将“已通知”视为“已完成”。

## 数据与验收边界

照片、档案、记录、提醒只在当前预览内存中存在，重载 / 关闭即清空；不会把输入内容、图片或修改后的宠物名字保存到宿主状态。宿主只记住固定主题标识、选中狗狗 ID 和 v0.7 新增的动态暂停偏好。

本轮验收覆盖照片选择及错误恢复、回忆归属、档案校验、改名后稳定归属、提醒完成与撤销、周期推进、误触防重、双主题和小屏布局。验证证据见[实施记录](../../steps/01-detail-pages.md)。浏览器验证不代替系统照片权限、通知、持久化、VoiceOver、Dynamic Type 和真机测试。
